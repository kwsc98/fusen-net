# ADR 0001：0.1 采用中心 Relay

- 状态：Accepted
- 日期：2026-07-20

## 背景

项目需要先把 QUIC + TUN 的三层网络做成可验证、可运维的开源基线。直接实现 mesh
会同时引入发现、身份传播、NAT 穿透、分布式路由、冲突解决和更大的安全边界，难以
在 0.1 阶段建立可靠测试。

## 决策

0.1 使用一个中心 Relay 汇聚控制面和数据面。Relay 维护静态节点身份、overlay
地址绑定和在线路由；Edge 只建立出站 QUIC 连接并创建本地 TUN。一个 Relay 表示
一个全互通信任域，overlay 仅支持 IPv4 单播。

内部使用角色中立的 `NodeRuntime`，将身份、监听、拨号、地址、路由和 TUN 能力
解耦。0.1 只暴露 `Relay` 和 `Edge` 模式，`Hybrid` 仅为未来扩展保留接口边界，
不提供配置或行为。

## 后果

- 优点：身份和路由有单一事实来源，源地址校验、重复节点处理和会话清理可确定测试。
- 优点：Edge 通常只需要出站 UDP，部署和故障定位更直接。
- 代价：Relay 是带宽瓶颈、可用性依赖和明文 overlay 流量的信任点。
- 代价：0.1 不提供点对点路径、Relay 高可用、跨租户隔离或动态路由。

引入分布式组网必须新增 ADR，不能把预留接口解释为兼容承诺。
